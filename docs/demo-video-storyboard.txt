시연영상 콘티 + 대본 (목표 3분, 최대 5분까지 허용)
화이트스페이스 (white space) — 제4회 경남 AI·SW 경진대회
제조·피지컬 AI 에이전트 부문
==================================================================

이 문서는 그대로 들고(또는 프린트해서) 녹화하면 되는 수준으로 적었습니다.
각 구간마다: [화면/행동] → 정확히 뭘 누르고 뭘 보여줄지, "대사" → 그대로
읽어도 되는 문장입니다. 대사는 꼭 토씨까지 맞출 필요는 없고, 자기 말투로
바꿔도 됩니다 — 의미만 유지하면 됩니다.

맨 아래 [부록 A]에 대사만 쭉 모아놓은 "읽기용 대본"이 따로 있습니다.
카메라 앞에서는 그 부분만 보고 읽으면서, 화면 전환 타이밍만 이 문서
본문의 타임코드에 맞추면 됩니다.

0. 촬영 전 준비 (최소 10분 전에 끝내둘 것)
==================================================================

[환경 점검]
  1. GPU 서버 SSH 터널 연결: 터미널에서
     ssh -f -N -L 8000:localhost:8000 GNU_server
     연결 후 브라우저에서 http://localhost:8000/health 접속 → 정상 응답 확인
  2. 로컬 Next.js 서버 실행: npm run dev → http://localhost:3000 접속 확인
  3. Supabase 상태 확인: 회차 목록 화면에 너무 지저분한 테스트 회차가
     많으면 녹화 전에 정리할지 결정 (리허설 회차 1~2개는 그대로 둬도
     "실제 사용 이력처럼" 보여서 괜찮음)
  4. 녹화 프로그램: Windows는 Win+G(Xbox Game Bar, 기본 내장) 또는 OBS
     Studio. 마이크 입력 켜져 있는지 꼭 확인 (음소거 상태로 녹화 시작하는
     실수가 제일 흔함)
  5. 브라우저 창 크기: 1280x800 이상 권장, 줌 100%, 북마크바/알림 끄기
  6. sample-data/inspection_batch_realistic_2.csv 파일 위치 미리 확인
     (탐색기에서 바로 찾을 수 있게 폴더 열어두기)

[리허설]
  - 전체 흐름을 한 번 말 없이 클릭만으로 리허설 → 업로드부터 트리아지까지
    실제로 몇 초 걸리는지 체크 (GPU 호출 구간은 3~8초 정도 대기 발생 가능)
  - 대기 시간엔 "GPU 서버에서 실제 응력 데이터를 대조하는 중입니다" 같은
    멘트로 자연스럽게 채우거나, 편집에서 그 구간만 빨리감기/컷 해도 됨

[예비 시나리오]
  - 녹화 중 GPU 연결이 끊기면: 당황하지 말고 /scenarios 화면의 고정
    예시(A/B/C)로 전환해서 이어가기 — 아래 [부록 B]에 대응 대사 있음

3. 촬영 팁
==================================================================

- 전체 흐름을 미리 한 번 리허설해서, 업로드→트리아지까지 걸리는 실제
  시간을 파악해두면 좋습니다(GPU 호출이 있어 몇 초 지연 있음 — 자연스럽게
  설명하며 기다리는 멘트 준비, 또는 편집 시 컷)
- 업로드 파일은 realistic_2.csv 추천(Pass/Conditional Pass 비율이 가장
  시연하기 좋게 섞여 있음)
- 마우스 커서를 천천히, 가리키려는 숫자/버튼 위에서 1~2초 멈춰주면 보는
  사람이 따라오기 쉽습니다
- 채팅 입력은 타이핑하는 모습을 그대로 보여줘도 좋고, 미리 붙여넣기 해도
  됩니다(실제 입력→AI 판단→결과가 보이는 게 핵심이지 타이핑 속도가
  중요한 게 아님 — 운영규정 제18조 기준)
- 말이 꼬이면 끊지 말고 이어가세요. 편집에서 자르는 게 녹화 중 여러 번
  다시 찍는 것보다 빠릅니다
- 영상 길이 3분이 원칙이지만 5분까지는 허용됩니다(운영규정 별지2) —
  다만 "본선 발표 시간에 포함"되므로 가능하면 3분 안쪽을 권장
- 녹화 끝나면 파일명은 알아보기 쉽게: whitespace_시연영상_최종.mp4 등

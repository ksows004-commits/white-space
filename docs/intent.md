# intent.md — 무엇을, 왜, 어떤 제약으로

## 배경 (기존 방식의 문제)

기존 발사체 부품 검수는 F/T(Fail/True, 합격·불합격 이분법) 시스템이다. 기준치에 못 미치면
부품을 그냥 폐기한다. 실제로는 부품마다 "완성도(재료 결함, 응력 감당 능력)"에 차이가 있고,
완성도가 낮아도 저응력 부위에는 충분히 쓸 수 있는 경우가 많다. 이걸 버리기만 하니 로스율이
불필요하게 높다.

## 목적

부품의 부위별 응력 감당치를 계산해서, "버릴지 말지"가 아니라 **"어디에 쓸지"**를 판단하는
시스템을 만든다. 완성도가 낮은 부품도 저응력 구역이나 다른 제품에 재배치해서 로스율을 줄인다.

## 이번 MVP에서 만드는 것 (범위)

- **대상 부품**: `ASSEMBLED_Rocket.STEP`의 `rocket_middlepart`(동체외벽) 1개 부품만 다룬다.
  나머지 부품(nozzle, fuel_pipe, fuel_t 등)은 이번 범위에서 제외한다.
- **소재**: 인코넬718(Inconel 718) 한 가지로 고정한다.
- **데이터**: 실제 제조사 데이터(MTR, CT 스캔 등)를 구할 수 없어 합성 데이터로 대체한다.
  - 인코넬718의 물성치(항복강도, 피로한계 등)는 공개된 재료 데이터베이스의 실제 값을 쓴다.
  - 이 물성치를 형상(동체외벽 CAD)에 입혀 PrePoMax(무료 FEA/응력해석 툴)로 실제 하중
    시뮬레이션을 돌려 응력 지도를 만든다.
  - 여기에 가상의 결함(위치·크기·종류)을 무작위로 주입해 여러 시나리오를 만든다.
  - → 형상은 단순화된 CAD를 쓰지만, 물성치와 물리 계산은 실제 값을 기반으로 하므로 결과에
    설득력이 있다.
- **판정 로직**: 시뮬레이션 응력 지도와 결함 위치를 대조해 구역별로 Pass / Conditional Pass /
  Fail 3단계로 판정한다. 구역은 임의로 나누지 않고 시뮬레이션 결과(응력이 몰리는 곳)에서
  자연스럽게 도출한다.
- **AI 에이전트**: Claude API(Anthropic SDK)를 직접 호출하는 tool-use 에이전트로
  판정 데이터를 근거 삼아 레벨3 검사 전문가용 분석 리포트(결함 원인, 조건부 승인
  여부, 재배치/수리 가이드)를 자동 생성한다. (※ 기획 초기엔 LangChain 사용을
  검토했으나, 실제 구현은 LangChain 없이 Anthropic SDK의 tool-use를 직접 다루는
  수동 루프로 구현했다 — 자세한 기술 설명은 docs/tech-description-material.txt 참고)
- **모델 접근 방식**: 처음부터 완전한 PINN(물리 법칙을 손실함수로 직접 넣는 신경망)을 새로
  설계하지 않는다. 먼저 PrePoMax 실제 시뮬레이션 데이터 위에 단순한 예측 모델(surrogate
  model)을 얹어 "즉시 예측"이 되는 것부터 완성하고, 남는 시간에 물리 손실함수(PINN 요소)를
  추가해 고도화한다.

## 이번 범위에서 제외하는 것 (향후 확장)

- 동체외벽 외 다른 부품 (nozzle, fuel_pipe, fuel_t, silicone_TUBE 등)
- 인코넬718 외 다른 소재
- 원자재 화학성분표(MTR), 결정구조·결정방향(EBSD), 단조/열처리 이력, X-ray/CT 스캔 등
  다른 데이터 모달리티 — 원래 계획서엔 전부 들어있었으나 실제 데이터 확보가 불가능해 이번
  MVP에서는 제외하고 "향후 확장 방향"으로만 남긴다.
- Human-in-the-Loop 검증 체계(레벨3 전문가 피드백 반영 루프)의 정식 구현 — 데모에서는
  개념만 보여주는 수준으로 간소화될 수 있다.
- **결함 방향(orientation)** — 지금은 항상 최악의 방향으로 가정(업계 표준 보수적 관행).
  방향별 응력까지 따지려면 계산이 훨씬 복잡해지는데 얻는 정밀도 대비 위험이 큼.
- **반복 하중 횟수(피로 사이클 수)** — 지금 쓰는 무라카미 공식 자체가 "무한 반복 기준
  피로한계"라, 사이클 수를 반영하려면 완전히 다른 공식(S-N 곡선 기반)이 필요하고 그
  공식에 필요한 실제 데이터(임무 프로파일, 소재 S-N 곡선)가 없어 지어낸 숫자가 들어갈
  위험이 있음 (2026-10-01, 사용자와 논의 후 보류 결정).

> **참고**: X-ray/CT 이미지는 실제 판정 로직(분석 파이프라인)에는 쓰지 않지만, 발표자료·
> 시연영상에서 이해를 돕는 시각 자료로 필요하면 별도로 만들 수 있다. 이건 분석에 쓰이는
> 데이터가 아니라 순수 설명용 그림이라는 점을 구분해야 한다.

## 향후 확장: 원시 이미지(CT/X-ray) 입력 (2026-10-02 논의, 로드맵 단계)

지금 판정 파이프라인은 "결함 좌표(x,y,z)·크기(√area)·표면/내부 종류"가 이미 정리된
CSV를 입력으로 받는다. 실제 현장에서는 이 숫자들을 레벨1/2 검사원이 CT/X-ray 원본
이미지를 보고 직접 읽어내는데, 이 단계까지 AI가 보조하면 더 완결된 시스템이 된다.
다만 지금은 만들지 않는다 — 데이터 문제 때문이다.

- **탐지(어디에 결함이 있는지)**: 기공·균열 같은 결함은 CT/X-ray에서 "주변과 밀도가
  다른 얼룩/선"으로 나타나는데, 이 시각적 패턴은 소재가 달라도 어느 정도 전이(transfer)
  된다 — 인코넬718이 아닌 다른 금속(알루미늄, 티타늄 등)의 공개 CT 결함 데이터로
  학습해도 "여기 수상한 부분이 있다"는 탐지 보조는 가능할 수 있다.
- **측정(크기를 몇 μm로 잴지, 표면/내부 구분)**: 이건 전이가 안 된다. CT 장비의 해상도
  (픽셀당 실제 거리)와 소재별 X-ray 흡수율 차이(인코넬은 니켈·크롬 함량 때문에 다른
  소재와 명암 대비가 다름) 보정이 필요해서, 다른 소재로 학습한 모델이 내놓는 크기
  숫자를 그대로 믿을 수 없다.
- **그래서 설계 방향**: "AI가 이미지를 보고 결함 후보 위치를 1차로 표시(초안) →
  검사원이 수치를 확인·수정 → 그 다음에야 판정에 들어감" 구조로 간다. AI가 측정값을
  확정하지 않고 사람이 항상 최종 확인하므로, 지어낸 숫자가 판정에 들어갈 위험이 없다.
- **진행 상황**: 사용자가 인코넬718이 아니더라도 쓸 만한 CT/X-ray 공개 데이터를 직접
  찾아보기로 함(2026-10-02). 데이터가 확보되면 범위를 다시 검토한다.

## 사용자

**레벨3 NDT(비파괴검사) 검사 전문가.** 실제 검사 체계에서 Level 1/2 검사원은 기준 충족
여부만 판정할 수 있고, Level 3 검사원만 "조건부 승인" 같은 엔지니어링 재량 판단을 내릴 권한이
있다. 이 시스템은 그 재량 판단을 데이터 기반으로 보조하는 도구다.

# spec.md — 화면 · 기능 · 데이터 · 걱정되는 점 · 확인 방법

## 화면

1. **시나리오 선택 화면**: 미리 준비된 부품 시나리오 3~4개 중 하나를 선택. 각 시나리오는
   서로 다른 하중 조건 + 서로 다른 가상 결함(위치·크기·종류) 조합.
2. **결과 화면**:
   - 동체외벽 3D 모델 위에 구역별 응력/판정 결과를 색으로 표시 (3D 뷰어 구현이 어려우면
     2D 단면도/그래프로 대체 — [spec.md 작성 전 합의 사항])
   - Claude가 생성한 레벨3 검사 전문가용 분석 리포트(결함 원인, 조건부 승인 여부,
     재배치/수리 가이드) 표시

## 기능

1. 시나리오 선택
2. 선택된 시나리오 데이터를 GPU 서버의 예측 API로 전송해 실시간 계산 요청
3. 계산 결과(구역별 응력값 + Pass/Conditional Pass/Fail 판정)를 받아 3D/2D로 시각화
4. LangChain으로 판정 데이터를 정형화 → Claude API 호출 → 전문가용 리포트 생성 및 표시

## 데이터 흐름

1. 팀원이 PrePoMax로 만든 응력 시뮬레이션 결과 CSV (`docs/fea-data-request.md` 형식,
   `node_id, x_mm, y_mm, z_mm, von_mises_mpa`)
2. 이 위에 시나리오별로 **고정된**(매번 랜덤이 아닌, 재현 가능한) 가상 결함(위치·크기·종류)을
   주입 — 리허설과 실제 촬영 때 결과가 달라지지 않도록 고정값 사용
3. 예측 모델(GPU 서버, surrogate model)이 구역별 응력·결함 데이터를 입력받아 Pass /
   Conditional Pass / Fail 판정 출력
4. Claude API 입력 프롬프트에는 위에서 계산된 **실제 수치를 그대로 포함** — Claude가 숫자를
   임의로 지어내지 않고 주어진 값만 바탕으로 서술하도록 지시

## 아키텍처 메모

- 프론트엔드(Next.js)는 Vercel에 배포, GPU 연산은 불가능한 환경
- 무거운 예측 연산은 GPU 서버(경상국립대 AI 서버)에 작은 API(FastAPI 등)로 띄워두고,
  Next.js 앱이 시나리오 선택 시 이 API를 실시간 호출하는 구조
- 시연은 3분 녹화 영상이라 발표 당일 실시간 안정성 부담은 적지만, **녹화 시점에는 GPU
  서버가 켜져 있고 API가 응답 가능해야 함**

## 걱정되는 점

- PrePoMax 응력 데이터 도착이 늦어지면 이후 전체 일정이 밀림
- GPU 서버 API 연동이 처음 해보는 작업이라 안정화에 시간이 걸릴 수 있음
- 3D 렌더링 난이도가 높으면 2D로 전환 필요 (이미 합의된 폴백)
- Claude가 실제 계산값과 다른 숫자를 지어낼 위험 → 프롬프트에 실제 수치 명시 + "주어진
  값만 사용" 지시로 완화
- 팀 전원이 1학년이라 PrePoMax, GPU 서버, Next.js, LangChain 모두 처음 다루는 도구 —
  각 단계마다 예상보다 시간이 더 걸릴 수 있음

## 확인 방법

- 시나리오별로 주입한 가상 결함의 심각도와 최종 판정(Pass/Conditional Pass/Fail)이
  논리적으로 맞는지 확인 (심각한 결함이 고응력 구역에 있으면 Fail로 나오는지 등)
- Claude 리포트에 언급된 수치가 실제 계산 결과와 정확히 일치하는지 대조
- 시나리오 선택 → 결과 표시까지 끊김 없이 동작하는지 리허설로 확인
- `npm run build` 오류 없이 통과 (CLAUDE.MD 공통 규칙)

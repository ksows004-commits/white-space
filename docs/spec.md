# spec.md — 화면 · 기능 · 데이터 · 걱정되는 점 · 확인 방법

## 화면

1. **시나리오 선택 화면**: 미리 준비된 부품 시나리오 3~4개 중 하나를 선택. 각 시나리오는
   서로 다른 하중 조건 + 서로 다른 가상 결함(위치·크기·종류) 조합.
2. **결과 화면**:
   - 동체외벽 3D 모델 위에 구역별 응력/판정 결과를 색으로 표시 (3D 뷰어 구현이 어려우면
     2D 단면도/그래프로 대체 — [spec.md 작성 전 합의 사항])
   - Claude가 생성한 레벨3 검사 전문가용 분석 리포트(결함 원인, 조건부 승인 여부,
     재배치/수리 가이드) 표시

## 기능

1. 시나리오 선택
2. 선택된 시나리오 데이터를 GPU 서버의 예측 API로 전송해 실시간 계산 요청
3. 계산 결과(구역별 응력값 + Pass/Conditional Pass/Fail 판정)를 받아 3D/2D로 시각화
4. LangChain으로 판정 데이터를 정형화 → Claude API 호출 → 전문가용 리포트 생성 및 표시

## 판정 기준 응력: von Mises → 최대주응력 교체 (2026-10-01)

개발계획서 원안에서 "너무 복잡해서 제외"했던 **결함 방향(orientation)** 항목을
다시 검토해 반영했다. 결함(균열)이 항상 최악의 방향(주응력에 수직)으로 나 있다고
가정하는 게 피로해석의 표준적인 보수적 관행인데, 지금까지는 이걸 von Mises
등가응력으로 근사해서 썼다. `.frd` 원본 파일에 이미 있는 6성분 응력 텐서에서
최대주응력(고유값)을 직접 계산해서 교체했다 — **새 데이터를 지어낸 게 아니라
이미 가진 실제 텐서 데이터를 더 정확하게 쓴 것.**

- **컬럼명은 그대로 `von_mises_mpa`를 쓰지만 실제 값은 최대주응력이다**
  (judge.py/api.py 등 기존 코드가 이 컬럼명을 광범위하게 참조하고 있어 안정성을
  위해 이름은 유지, 값의 의미만 바꿈 — 값의 의미가 바뀌었다는 걸 숨기지 않기
  위해 이 문서에 명시한다).
- **실측 비교 (116개 구역, 4하중 envelope 기준)**: 중간값은 비슷하지만(von Mises
  28.2 vs 최대주응력 27.6 MPa) 최고응력 지점(핫스팟)에서 최대주응력이 더 높게
  나온다(1012 → 1266 MPa, +25%). 결함 크기별로 판정이 바뀌는 구역 비율을
  계산해보면(300~1800μm 결함 기준) 3~9%가 바뀌는데, **바뀌는 경우 거의 전부
  더 엄격한 쪽(Pass/Conditional → Conditional/Fail)으로 이동**한다 — von Mises
  기준이 실제보다 살짝 낙관적이었을 가능성을 시사하는, 안전 쪽으로의 보정이다.
- 이 교체로 시나리오 B/C, 샘플 파일 4종의 결함 크기 보정값을 다시 맞췄다
  (SCENARIO_DEFECTS, generate_sample_data.py 참고).

## 응력 예측 surrogate 모델 (탐색적 기능, 2026-10-01 추가, 10-01 재학습)

- 기존 판정 경로(`/judge_defects`, `/judge_batch` 등)는 결함 좌표를 가장 가까운 실제 FEA
  노드/패널 값에 스냅해서 판정한다. 이건 그대로 유지하고 **주 판정 경로로 계속 쓴다.**
- 별도로, 좌표(x,y,z) → 응력값을 바로 예측하는 작은 신경망(MLP)을 실제 FEA 데이터
  32만여 개 노드로 학습해 병렬 엔드포인트(`/judge_defects_fast`)로 추가했다. "제조 피지컬
  AI 에이전트" 부문 취지에 맞는 AI 모델 활용 사례를 보여주기 위한 탐색적 기능이다.
- **실측 정확도 (검증셋 48,485개 노드 기준, 최대주응력 교체 후 재학습한 최신 값)**:
  - surrogate MLP: MAE 7.36 MPa, RMSE 15.46 MPa, 최대오차 743.77 MPa, R² 0.804
  - 비교 기준(최근접 노드 스냅): MAE 5.33 MPa, RMSE 17.14 MPa, 최대오차 467.0 MPa,
    R² 0.759
  - **해석**: von Mises 기준(교체 전 MAE 5.54, 최대오차 328.89)보다 오차가 커졌다.
    최대주응력(텐서 고유값)이 von Mises보다 공간적으로 덜 매끄러운 함수라 신경망이
    배우기 더 어려운 것으로 보인다. surrogate 경로는 여전히 참고용일 뿐 주 판정에
    쓰지 않으므로 실사용에는 영향 없지만, 정확도가 떨어졌다는 사실은 숨기지 않고
    기록한다.
- **알려진 한계 (2026-10-01 재검증 중 발견)**: D(신뢰도 기반 에스컬레이션)는
  예측값이 "판정 경계 근처"일 때만 정밀 재계산으로 넘어간다. 그런데 실제 좌표
  (13.6005, 215.5674, 13.9435)에서 surrogate가 14.2 MPa로 예측했지만 실제값은
  252.8 MPa(약 238 MPa 차이, 최대오차 범위 안의 이상치)였는데, 이 예측값이
  판정 경계 두 곳 모두에서 멀리 떨어져 있어 에스컬레이션이 발동하지 않았다.
  즉 D의 안전장치는 "경계 근처의 애매함"은 잡아내지만 "모델이 그냥 크게 틀린
  경우"는 잡아내지 못한다. surrogate/D 둘 다 탐색적 기능이고 실제 업로드 판정
  경로(`/judge_defects`)는 항상 정밀 조회를 쓰므로 이 한계가 실사용 판정에
  영향을 주지는 않지만, 두 기능을 더 신뢰도 높은 용도로 쓰려면 반드시 먼저
  해결해야 할 문제로 기록해둔다.

## 데이터 흐름

1. 팀원이 PrePoMax로 만든 응력 시뮬레이션 결과 CSV (`docs/fea-data-request.md` 형식,
   `node_id, x_mm, y_mm, z_mm, von_mises_mpa`)
2. 이 위에 시나리오별로 **고정된**(매번 랜덤이 아닌, 재현 가능한) 가상 결함(위치·크기·종류)을
   주입 — 리허설과 실제 촬영 때 결과가 달라지지 않도록 고정값 사용
3. 예측 모델(GPU 서버, surrogate model)이 구역별 응력·결함 데이터를 입력받아 Pass /
   Conditional Pass / Fail 판정 출력
4. Claude API 입력 프롬프트에는 위에서 계산된 **실제 수치를 그대로 포함** — Claude가 숫자를
   임의로 지어내지 않고 주어진 값만 바탕으로 서술하도록 지시

## 아키텍처 메모

- 프론트엔드(Next.js)는 Vercel에 배포, GPU 연산은 불가능한 환경
- 무거운 예측 연산은 GPU 서버(경상국립대 AI 서버)에 작은 API(FastAPI 등)로 띄워두고,
  Next.js 앱이 시나리오 선택 시 이 API를 실시간 호출하는 구조
- 시연은 3분 녹화 영상이라 발표 당일 실시간 안정성 부담은 적지만, **녹화 시점에는 GPU
  서버가 켜져 있고 API가 응답 가능해야 함**

## 걱정되는 점

- PrePoMax 응력 데이터 도착이 늦어지면 이후 전체 일정이 밀림
- GPU 서버 API 연동이 처음 해보는 작업이라 안정화에 시간이 걸릴 수 있음
- 3D 렌더링 난이도가 높으면 2D로 전환 필요 (이미 합의된 폴백)
- Claude가 실제 계산값과 다른 숫자를 지어낼 위험 → 프롬프트에 실제 수치 명시 + "주어진
  값만 사용" 지시로 완화
- 팀 전원이 1학년이라 PrePoMax, GPU 서버, Next.js, LangChain 모두 처음 다루는 도구 —
  각 단계마다 예상보다 시간이 더 걸릴 수 있음

## 확인 방법

- 시나리오별로 주입한 가상 결함의 심각도와 최종 판정(Pass/Conditional Pass/Fail)이
  논리적으로 맞는지 확인 (심각한 결함이 고응력 구역에 있으면 Fail로 나오는지 등)
- Claude 리포트에 언급된 수치가 실제 계산 결과와 정확히 일치하는지 대조
- 시나리오 선택 → 결과 표시까지 끊김 없이 동작하는지 리허설로 확인
- `npm run build` 오류 없이 통과 (CLAUDE.MD 공통 규칙)

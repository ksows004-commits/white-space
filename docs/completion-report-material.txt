------------------------------------------------------------------

- 팀명: 화이트스페이스 (white space)
- 대회: 제4회 경남 AI·SW 경진대회 — 제조 피지컬 AI 에이전트 부문
- 제출 마감: 2026-10-06 12:00
- 팀 구성: 3명(신소재공학부 1명, 항공우주공학부 2명, 전원 1학년).
  대표(팀 리더)는 비개발자. 소스코드 개발은 Claude Code(AI 코딩 어시스턴트)
  와 Codex(보조 AI 코딩 어시스턴트)를 활용해 진행.
- 대상 문제: 발사체 부품 검수는 전통적으로 F/T(Fail/True) 이분법 — 기준
  미달 시 전량 폐기. 부품마다 완성도 차이가 있고 저응력 부위에는 결함이
  있어도 충분히 쓸 수 있는 경우가 많음에도 불필요하게 로스율이 높다는
  문제의식에서 출발.
- 핵심 가치 제안: "버릴지 말지"가 아니라 "어디에 쓸지"를 AI가 판단하는
  시스템. 같은 부품이 여러 위치/조건에 쓰이는 제조 상황 전반에 적용
  가능한 원칙이며, 발사체 동체외벽을 데모 사례로 선정(효과가 극적으로
  드러나는 사례).
- 대상 부품: 동체외벽(rocket_middlepart), 인코넬718(Inconel 718)
- 데이터 기반: 팀원이 PrePoMax(CalculiX)로 생성한 실제 FEA 시뮬레이션
  결과(4개 하중케이스, 노드당 32만여 개) — 전 과정에서 합성/가상 수치가
  아닌 실측 데이터와 공개된 공학 공식(무라카미 모델)만 사용

  실제 승인/반려 기록·조회 테스트 완료

  y=축방향 정합성 확인)

5. 프로젝트 관리 특이사항 / 품질 관리 사례
------------------------------------------------------------------

- 개발 방식: 팀 리더(비개발자)가 요구사항·우선순위를 결정하고, Claude
  Code가 아키텍처·판정 로직 설계·검증을 담당, Codex가 명확히 정의된
  구현 작업을 분담(역할 분리로 명시된 CODEX.md 운영 규칙 존재) — 모든
  Codex 결과물은 Claude Code가 리뷰·테스트 후 커밋
- 데이터 진실성 원칙을 전 과정에서 일관 적용: 실제 데이터가 없는
  영역(다른 소재, CT/X-ray, 피로 사이클 등)은 기능을 만들지 않고 명시적
  보류/제외로 문서화. "그럴듯한 가짜 정밀도"를 만들지 않는다는 원칙을
  surrogate 모델 한계 공개, D(에스컬레이션) 한계 재검증·정정 등에서
  일관되게 적용
- 발견·수정한 주요 버그(상세 기술설명서 참고): 샘플 데이터 좌표 중복,
  GPU 서버 하중케이스 파일 누락, 2D 지도 좌표축 오류, 채팅-HITL 연동
  레이스 컨디션, surrogate 학습 데이터 음수값 처리, 인코딩 깨짐 등 —
  전부 재현·원인 확인 후 수정, 재발 방지 조치 포함
- 판정 체계는 1차 설계(결함의 "현재 위치" 기준) 운영 중 실사용에서 발견된
  모순적 표시 문제를 계기로, 팀 리더와의 논의를 거쳐 2차 재정의("116개
  설치 구역 커버리지" 기준)로 개선 — 사용자 피드백 기반 반복 개선 사례
- 조원(팀원) 평가 피드백("설치 구역 표시 가독성 개선") 반영: 2D 지도
  재설계 과정에서 단순 UI 개선이 아니라 실제 좌표 매핑 버그를 발견해
  근본 수정

# scenarios.md — 시연용 시나리오 설계

## 기준

시나리오는 **같은 부품(동체외벽, `rocket_middlepart`) 안에서 위치별로 다른 응력**을
보여주는 것을 기준으로 한다 (부품이 다른 제품에 쓰이는 경우가 아니라, 한 부품 안에서
구역마다 응력이 다르다는 것). 데이터는 `docs/fea-data-request.md`의 **케이스 1(내부
압력)**을 기본으로 하고, 팀원이 케이스 2~4(추력/진동/극저온)까지 만들어주면 "같은 부품이
다른 하중 환경에 놓였을 때"로 확장한다.

결함 위치·크기는 **시나리오별로 고정값**을 쓴다 (매번 랜덤이면 리허설과 실제 녹화 때
결과가 달라져 위험하므로). 정확한 좌표는 팀원의 실제 CSV 데이터를 받은 뒤, 아래 규칙에
맞는 노드를 찾아서 채운다.

## 구역(패널) 크기 — 25mm × 25mm

지금까지는 FEA 메쉬의 점(node) 단위로 판정했는데, 실제 검사원은 점이 아니라 **실제로
제작된 판(패널) 하나**를 보고 판정한다. 이 단위를 맞추기 위해 노드를 격자로 묶는다.

- **격자 크기: 25mm × 25mm** — 항공우주 주조품 결함 등급 표준(ASTM E155/E192 계열)에서
  쓰는 표준 평가 구역(1 inch × 1 inch)을 그대로 사용. 임의로 지어낸 숫자가 아니라 실제
  업계 관행에 근거한 값이다.
- **우리 CAD 치수와의 정합성 확인**: `ASSEMBLED_Rocket.STEP` 전체 좌표 범위를 계산한
  결과, 지름 방향 약 73mm, 길이 방향(어셈블리 전체) 약 330~610mm. 25mm 격자를 적용하면
  지름 방향 약 3칸, 길이 방향 약 8~12칸(동체외벽 구간 기준)이 나와 "위치별로 다르다"는
  스토리를 보여주기에 충분한 해상도다.
- 격자 하나 안에 있는 노드들의 응력값은 **최댓값을 대표값으로 사용**한다 (평균을 쓰면
  결함이 있는 위험한 지점이 희석되어 안전 쪽으로 잘못 판정될 수 있으므로, 보수적으로
  최댓값을 쓴다).

## 시나리오

| ID | 이름 | 결함 위치 규칙 | 결함 크기/종류 | 예상 판정 | 보여주려는 것 |
|---|---|---|---|---|---|
| A | 정상 부품 | 결함 없음 | - | 전 구역 Pass | 베이스라인 |
| B | 치명적 결함 | 케이스 1 응력 **최댓값** 노드 근처 | 큼 (표면 균열, √area 500μm) | 그 구역 **Fail** | "기존 F/T였으면 여기서 폐기" |
| **C** | **재배치 가능 결함** | 케이스 1 응력이 **낮은 지점**(하위 25% 이하) 근처 | 중간 (내부 기공, √area 200μm) | 그 구역 **Conditional Pass** | **핵심 스토리**: 원래 기준엔 미달이지만 이 자리는 충분히 견딤 → 재배치 |
| D (선택, 시간 남으면) | 경계 케이스 | 응력 중간값 지점 근처 | Pass/Conditional 경계에 걸치도록 크기 조정 | 경계선 | 판정 로직의 정교함 어필 |

## 데이터 확정 절차 (팀원 CSV 도착 후)

1. 케이스 1 CSV의 노드들을 25mm × 25mm 격자로 묶고, 격자별 대표 응력값(최댓값) 계산
   — `judge.py`에 이 격자 묶기 로직을 추가해야 함 (아직 없음, 다음 Codex 작업 대상)
2. 격자별 `von_mises_mpa` 최댓값/최솟값/중앙값 확인
3. 위 표의 규칙에 맞는 실제 격자(패널) 선택
4. `judge.py`의 `match_defects_to_nearest_nodes()`에 시나리오별 결함 좌표·크기·위치
   종류를 넣어 판정 결과가 표의 "예상 판정"과 일치하는지 확인
5. 일치하지 않으면 결함 크기를 조정해 스토리에 맞게 보정

## UI 표시 이름 (참고)

Codex가 만든 화면 목업엔 "시나리오 A/B/C"로 임시 표시되어 있음. 실제 데이터 연동 시
아래처럼 이름을 바꿀 것을 권장:

- A → "정상 부품"
- B → "고응력부 결함 부품"
- C → "재배치 가능 부품" (또는 더 눈에 띄는 이름으로)
